# Git 提交规范

提交信息遵循基于 Conventional Commits v1.0.0 修改的以下规范，未明确的部分按原规范执行。

## 标题格式

- 标题格式为 `<type>(<scope>): <desc>`
  - 例如 `NEW(doc): 增加项目文档格式定义`
- 在包含多个逻辑模块的仓库中可扩展为 `<type>(<module>-<scope>)`，module 为仓库内额外明确约定的独立模块名
  - 是否启用 module 段以项目内规范为准，未约定时不要主动使用

### type

- type 仅允许 `NEW`、`FIX`、`REF` 3 种
  - `NEW` 仅用于新增功能、文档或测试的情况
  - `FIX` 仅用于修复任何内容的错误的情况
  - `REF` 仅用于超出修复范畴，且不以新增功能为主的重构
- 无法确定修改类型时，跳出对话与用户讨论，不自行任意确定

### scope

- scope 仅允许 `doc`、`src`、`test`、`tool`、`misc` 5 种
  - `doc` 仅用于文档内容的新增与修改
  - `src` 仅用于项目或模块主体源代码的情况
  - `test` 仅用于项目或模块的测试代码、测试数据与测试配置的情况
  - `tool` 仅用于项目或模块的构建脚本、开发工具、CI 与项目配置等辅助设施的情况
  - `misc` 仅用于无法归入单一 scope 的跨范围修改
- 项目可在自身规范中声明额外的 scope，未声明时不自行发明
- 根目录下的文件按语义归入对应 scope，例如 `README.md` 归 `doc`、构建配置归 `tool`
- 单次提交尽量只覆盖一个 scope，仅当用户要求的修改确实跨范围且不易拆分时才使用 `misc`
- 无法确定 scope 归属时，跳出对话与用户讨论，不自行任意确定

### desc

- 使用中文简短清晰地描述提交内容和目的，必要时才用英文补充
- 不写主语，默认以"本次提交"为主语
- 标题全长建议不超过 100 个字符，中文字符按 2 个字符计算

## 正文

- 标题足以说明修改时不写正文
- 需要正文时说明修改动机与影响范围，遵循 [Markdown 文档规范](markdown-writing.md) 的要求
- 永远不附加 `Co-authored-by` 等合作作者信息，也不附加 "Generated with" 等 AI 工具署名尾注
