# 任务路由与投入档位

## 先识别用户真正要完成的任务

### 精确定位

适用于 DOI、UT、精确题名或高度明确的作者/期刊组合。

- 使用快速档。
- 通常跳过 count-only 和分片筛选。
- 未限定 citation index 且只需常用元数据、摘要和 WOSCC 被引次数时使用 JSON。
- 用户指定 SCIE/ESCI 等 index，或需要关键词、卷期页、Z9、CR 时使用 TSV。

### 引用信息快照

先区分用户所说的“被引”：

- `TC` / JSON `times_cited`：WOSCC 被引次数。
- `Z9`：所有 Web of Science 数据库中的被引次数，只能从 TSV 获取。
- `CR`：该记录引用的参考文献，不是“引用该记录的论文列表”。需要时使用 `fullRecordPlus`。
- 当前技能不承诺完整的施引文献列表。用户明确要“哪些论文引用了它”时，说明当前适配器只可靠支持被引次数和 CR，不要把 CR 当成施引文献。

### 主题发现

适用于按主题、作者、期刊、年份查找代表性论文。

- 默认使用标准档。
- 用户条件已清楚时直接提出检索计划，不重复逐项提问。
- 宽主题可采用最近 5 年、Article + Review、取回不超过 200 条作为可修改默认值。
- count 过高时优先收窄概念、年份和文献类型；不要依靠只取前 N 条来伪装完整覆盖。

### 研究进展或概念演进

适用于“现状、趋势、演进、最新证据、代表方法、争议”等问题。

- 用户只要快速概览时使用标准档，并明确覆盖有限。
- 用户要求较系统的结论时升级到深入档。
- 深入档可构造多个相邻查询变体，顺序执行、合并后按 UT/DOI 去重。
- 最新进展使用近年 `PY` 范围并按 `date` 排序；基础工作另用 relevance/被引信息识别，不要把二者混成同一排名。

### 批量导出

- 只有用户明确要求文件或系统性采集时才交付导出物。
- 1–1000 条仍按标准/深入路径执行。
- 超过 1000 条前确认总量、字段范围、是否需要筛选和预期耗时；单批始终不超过 1000 条，总量不超过 100000 条。
- 批量导出不等于研究总结。用户只要数据时不要强制做逐条语义筛选。

## 三档默认值

| 档位 | 典型任务 | 查询 | 候选规模 | 筛选方式 |
| --- | --- | ---: | ---: | --- |
| 快速 | 精确记录、少量元数据、单篇被引快照 | 1 个 | ≤20 | 主代理直接核对 |
| 标准 | 主题找论文、有限综述 | 1 个主式，最多迭代 2 次 | ≤200 | 硬过滤 + 三态筛选 |
| 深入 | 研究进展、概念演进、系统收集 | 多个经确认的变体 | 默认 ≤1000 | 去重、分片、三态筛选、综合 |

用户明确指定档位时服从。未指定时使用标准档；精确任务自动降为快速档。不要仅因命中数高就自动升级到深入档。

## 模式 B 的提醒和执行

满足以下全部条件时才提醒：

1. 当前对话正在形成科研或技术结论；
2. 最新 WoS 索引研究证据可能实质改变、限定或支撑结论；
3. 当前没有已经足够的新近可靠来源；
4. 本次讨论尚未提醒或被用户拒绝。

提醒时简述三个档位和代价，不先执行 access check。用户确认后：

- 由一个网络 worker 顺序完成权限探查、查询和记录获取；
- 网络 worker 返回检索元数据、规范化 JSONL 路径和计数；
- 主代理统一组织本地筛选 worker，禁止把网络访问扩散到多个 worker；
- 不支持后台或嵌套代理时退化为主代理顺序执行；
- 对用户保持简洁，但不能省略来源和方法摘要。

若用户明确要求同行评议材料，应把 Article/Review 等文献类型作为检索或硬过滤条件并报告该条件；不要仅凭 WOSCC 收录状态断言已核验同行评议。
