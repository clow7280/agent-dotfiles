# GB/T 7714—2025 引用与参考文献

按标准的规范性强度审校，不把可选做法误报为错误。
先恢复每条文献的语义字段，再按目标模板重建，不要只做标点替换。

## 加载参考资料

1. 每次任务先读 [references/core-rules.md](references/core-rules.md)，掌握通则、规范性用词和合法变体
2. 只读任务涉及的类型章节，从 [references/formats.md](references/formats.md) 选择相应模板和必备性表
3. 涉及正文标注、排序、编号、脚注或两种体系转换时，读 [references/citation-systems.md](references/citation-systems.md)
4. 涉及类型识别或 `[J/OL]` 等代码时，读 [references/codes.md](references/codes.md)

不要把参考文件中的模板占位词原样输出。
只输出用户实际提供或可靠核实的字段。

## 确定任务边界

先识别输入范围：

- 完整正文与参考文献表: 执行全文闭环检查
- 只有参考文献表: 检查条目和表内排序；顺序编码制没有正文时，不声称已验证编号先后
- 只有正文或片段: 检查标注形式和内部一致性，不虚构文后条目
- 只有单条文献: 按可见元数据重建并列出仍缺字段
- DOCX、LaTeX 或其他结构化文档: 尽量保留域代码、交叉引用、超链接、脚注、修订和样式；除非用户明确要求，不把自动编号静态化

遵从用户、期刊、学校或出版社明确指定的引用体系及局部规则。
未指定时保留输入中一致且占主导的体系。
若输入混用两种体系，选择能最少改动且可形成闭环的一种，并在结果中说明。

## 执行审校

按本章小节顺序执行。

### 建立清单与预检

为每条文献记录原位置、正文标记、责任者、题名、类型、载体、版本、来源与出版项、日期、页码或文章编号、URL、PID。
区分三类条目：

- 实际引用的“引文参考文献”
- 仅供延伸阅读的“阅读型参考文献”
- 无法判定用途的条目

先合并由换行拆开的同一条目和 URL，不合并仅因题名相似的不同版本。

对纯文本、Markdown 或已提取文本，可运行确定性预检：

```bash
python3 <SKILL_DIR>/scripts/gbt7714_lint.py INPUT --system auto
```

`<SKILL_DIR>` 指当前加载的 `SKILL.md` 所在目录的绝对路径，不要假定 shell 当前目录就是技能目录，也不要写死安装路径。
用 `--format json` 获取机器可读结果，用 `-` 从标准输入读取。
`--standardization-document` 用于确认输入本身是标准化文件，从而接受标准条目省略 `[S]`；`--web-context` 用于确认正在按 8.11 审查网站或网页形态。
该脚本只报告可由文本确定或提示人工复核的结构问题，不能替代语义审校，也不会自动改写原文。

### 分类并核对字段

按资源本身而非链接外观选择文献类型。
例如在线期刊论文仍是 `[J/OL]`，在线学位论文仍是 `[D/OL]`，不能都写成 `[EB/OL]`。
先按第 8 章的“形式优先”规则判断是否应沿用图书、析出文献或连续出版物格式，再使用网站、档案、地图、数据集、预印本等专门模板。

逐项区分规范性强度：

- `应`、`不应`、`必备`: 不符合即错误
- `有则必备` 与 `电子资源必备`: 已存在相应事实或属于电子资源时才强制
- `宜`: 给出建议，不强称唯一答案
- `可`、`可选`: 保留任一合法形式，除非用户要求统一

### 核实事实而非猜测

只从用户材料、资源本身或可靠检索结果补字段。
不得根据常识猜作者、出版地、卷期、页码、访问日期、DOI 或 URL。

将无法确认的内容放入“待核项”，不要把 `[待核]`、问号或虚构占位符塞进最终参考文献。
若仅做格式转换，保留原有事实并明确指出信息不足。

特别禁止两种“补齐”：

- 不把当前系统日期、本次审校日期或代理访问网页的日期当成作者的引用日期；只有用户明确确认实际访问日期时才能写入
- 不因“恰好有一个悬空引文和一个未引条目”就认定二者对应；只有题名、责任者、旧编号映射或其他证据能建立同一性时才重编号

若缺失事实使完全合规的“干净版”无法生成，只交付可确定更正的部分并说明尚未完全合规，不要通过暂定事实后再宣称零错误。

### 重建条目

按 [references/formats.md](references/formats.md) 的对应模板重建：

1. 保留信息资源本身的语种和西文大小写习惯
2. 规范责任者、题名、类型与载体、出版项、日期、页码、URL 与 PID 的顺序
3. 使用前置标识符，删除空字段连带的分隔符
4. 对电子资源同时著录类型和载体，按具体类型补其强制日期与访问路径
5. URL 已含 DOI 或 URN 时允许不再重复 PID，不要把这种合法省略判错

### 同步正文与文后表

按 [references/citation-systems.md](references/citation-systems.md) 执行：

- 顺序编码制按首次出现顺序编号，复引沿用首次序号；核对缺号、重号、未引条目和悬空引文
- 著者-出版年制同步责任者、年份及 `a`、`b`、`c` 后缀，并按文种、责任者和出版年排序
- 将引文页码放在标准指定的位置，不把 APA 式页码语法直接带入
- 仅有参考文献表时，不擅自重新编号成“首次出现顺序”

重新编号前先证明每个旧正文标记对应哪个文献实体。
映射不明时保留旧标记与条目，分别报告“悬空引文”和“未引条目”，不要按空缺位置配对。

## 执行转换

从其他格式转换时，先解析为字段，再生成目标格式：

1. 标记输入体系和目标体系
2. 建立旧标记到文献实体的映射，去重时保留版本、载体和引用页差异
3. 重建文后条目
4. 重写正文标记并同步排序与编号
5. 再做一对一闭环核对

从顺序编码制转为著者-出版年制时，处理同著者同年后缀；反向转换时，按正文首次出现重新编号。
缺少正文时只转换条目外观，不承诺编号正确。

## 输出与交付前复核

除非用户只要“干净版”，按以下顺序交付：

1. 结论: 体系、条目数、错误数、警告数、待核数
2. 按输入范围提供更正后的正文引文、参考文献表或两者
3. 问题清单: 位置、原文、建议、依据条款、严重性、置信度
4. 待核项: 说明缺失事实及其影响

使用 `错误`、`建议`、`待核` 三类，不把风格偏好包装成国标硬性要求。
条款依据至少精确到章条，如 `7.1.2`、`8.5.3`、`9.2.1.3`。

交付前逐项确认：

- 每条文献只套用一个主模板，析出文献的宿主信息完整
- 电子资源有载体标识及该类型要求的访问路径与引用日期
- 日期为 `YYYY-MM-DD`，估计出版年与自拟题名使用方括号
- 正文标记与文后条目双向对应，排序、复引和页码位置一致
- 所有改动都可由输入事实或核实来源支持
- 没有用当前日期代填引用日期，也没有按编号空缺猜测条目映射
- 没有把“可”“宜”升级为“应”
