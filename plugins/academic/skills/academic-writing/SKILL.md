# 理工科中文学术写作

## 1 基本原则

大语言模型按统计规律选择最稳妥的字符序列，用它代替具体的思考，所以输出的文字常常是缺少逻辑的信息堆砌。
本 Skill 把空泛、装饰性、需要读者推断的表达，换成具体、直接、连贯且字面成立的表达。
本 Skill 的痕迹清单不可能穷尽所有情况，遇到未覆盖的可疑写法时，请依据基本原则判断。

1. 表达内容必须有来源。
即事实、数据与结论只来自用户提供的素材、可信资料或逻辑推断，不补充看似合理但没有来源的信息。

2. 使用中性、准确的语体，但这不等于把所有文本改成同一种腔调。
素材所属领域或用户指定领域的学科术语、立场与论证习惯都要保留，不故意加入错误或口头禅来模仿真人。

3. 学术写作重在逻辑而不是详尽。
节与节之间靠大纲串联，节内的段落和段落内的句子靠逻辑衔接，大纲本身的设计也要有逻辑关联。
把缺少逻辑联系的分析、数据或结论直接罗列在文稿中，读者很难读下去。
无论其中包含多少重要内容，读者抓不住作者的表达意图，就无法准确理解观点，数据也就失去了意义。
学术写作可以使用比喻、强调与修辞性的标点，但它们不能替代论证和分析。

## 2 写作流程

### 2.1 写作前的判断

从用户的要求和已有素材中判断目标文体与所写部分、论证目标、读者和素材来源，能确定的不要求用户重复提供。
文体指所写的是期刊论文、学位论文、文献综述还是研究报告，所写部分指摘要、引言、方法、结果或讨论。
部分确定之后，论证目标通常随之明确，即这一部分要提出问题、报告结果、比较方法，还是建立一个判断。
论证目标确定写什么之后，还要根据读者决定写多细。
默认读者是同领域的研究者，写作前要判断他们已经知道什么、哪里容易误解，不解释同行显然知道的内容。
素材来源要分清哪些是实验数据和已核实的文献，哪些只是推测或转述，文中的判断能写得多确定取决于此。

信息不足时，选择不改变事实与作者立场的保守写法。
只有不同判断会导致实质不同的写法，且保守写法无法兼顾时，才向用户确认。
修改已有文本时，删去没有依据的判断不算改变作者立场。
被删的判断属于作者的核心主张时，先向用户确认。

起草时，论证需要的文献、数据或实验细节如果素材中没有，不编造，也不写成没有内容的空话。
在相应位置留下占位符，例如“【待补文献：最早提出相对位置编码的工作】”，写明缺什么、用来支撑什么。
缺失的素材会决定论证方向时，先向用户索取，再起草。

### 2.2 起草与修改流程

判断完成后，起草新文本和修改已有文本都按下面的步骤进行。

1. 想清楚各段之间如何推进，从头起草整章或整篇时，把推进关系拟成大纲，与用户确认后再起草
2. 按“句段要求”“人类作者的写法”与“常见痕迹”三章的要求起草或改写，改写时保留原文的核心信息与作者立场
3. 写完整篇成稿后再通读一遍，逐段对照这三章修改，并检查章节分工与全文称呼是否一致
4. 完善模式下，按“检查模式”一节请子代理审查成稿，并处理报告的问题
5. 交付成稿，并在成稿之后附上交付说明

三章的要求主要在起草时起作用，通读只用来补上起草时的遗漏，不能代替起草时的遵守。

交付说明只写用户核对成稿时需要知道的事项，按下面三组列出，每项一句，没有内容的组省略。

- 改动：改变了事实、判断或结构的修改，例如删去的判断、合并或删除的段落，措辞层面的修改不逐条列出，完善模式下还写明主代理复核了哪些段落
- 待确认：需要用户决定或补充的事项，例如文中的占位符、保守写法下仍有分歧的判断
- 待核：需要用户核对的内容，例如本次检索得到的文献信息、由素材换算出的数据、未经独立审查的成稿

三组都没有内容时，省略交付说明。

### 2.3 检查模式

检查分为简易模式与完善模式，默认使用简易模式。
用户要求更严格的检查，或明确指定完善模式时，使用完善模式。

简易模式只做“起草与修改流程”中的通读。
完善模式在通读之后，再请一个没有参与写作的子代理审查成稿。
子代理不受写作时判断的影响，更容易发现需要通读全文才能看出的问题，例如段落之间的推进是否成立、判断与素材是否一致、同一内容是否在多处重复。

交给子代理的只有成稿、用户提供的素材与写作要求，以及本 Skill 的 SKILL.md，不包括写作过程中的草稿与推理。
子代理按下面的要求审查和报告。

- 对照“句段要求”“人类作者的写法”与“常见痕迹”三章审查，只报告问题，不改写全文
- 最多报告 15 条，先报告事实、逻辑与引用问题，再报告措辞问题，超出的部分只说明还有多少条
- 每条写明位置、问题和对应的小节名，位置用原文中的一句话标出
- 同一句话在成稿中出现多次时，位置写成所在小节加“首次出现”或“第几次出现”
- 不再请其他子代理
- 没有发现问题时，只回复“未发现问题”

主代理逐条判断报告的问题，问题成立就修改，不成立就不采纳。
子代理的审查只做一轮。
只涉及措辞的修改，改完不再复核。
改变了结构、事实或引用的修改，由主代理对照同样的三章复核改动过的段落。
当前环境不支持子代理时，退回简易模式。

### 2.4 完整示例

下面是一段待修改的结果描述。

> 核心发现：本研究构建的融合框架显著提升了分类性能。
> 这一框架有效捕捉了模态间的深层关联，该机制驱动了模型表征能力的跃升，这种设计更是重塑了多模态学习的范式。
> 此外，在两个公开数据集上，准确率分别提高 3.2 和 2.7 个百分点。
> 值得注意的是，参数量增加了 40%。

修改后的版本只保留原文已有的事实。

> 本研究将多种模态的特征融合后用于分类。
> 在两个公开数据集上，融合后模型的准确率分别提高 3.2 和 2.7 个百分点，但参数量也增加了 40%。

修改时删除了段首的“核心发现：”标签。
第一句的“显著提升”没有显著性检验支撑，改由后文的具体数据说明。
原文第二句的三个分句以框架、机制、设计为主语，作出的判断都没有实验支撑，所以一并删除。
其中“驱动了跃升”“重塑了范式”也不是研究者会用的搭配。
原文用“此外”引出支撑结论的数据，把它当成了补充信息，改写后直接陈述。
参数量增加与准确率提高之间是转折关系，原文用“值得注意的是”一笔带过，改写后用“但”直接交代。

## 3 句段要求

### 3.1 逻辑衔接

句子与句子、段落与段落之间必须有逻辑衔接。
读者不应该自己去猜两句话或两段话之间是转折、因果、递进还是补充。

衔接采用什么形式、放在什么位置，由这层关系在表达中的目的和重要程度决定。
关系本身就是要传达的信息时，例如结果与读者的预期相反、需要解释原因，值得用一句话专门交代。
关系只起串联作用时，一个连接词或一个承接上文的短语就够了。
读者需要先知道关系才能理解下文时，衔接放在句首或段首。
关系只是附带说明时，衔接可以放在句中或句末。

无论采用哪种形式，衔接都要交代真实的关系。
“下面来看另一个方面”这类只起导航作用的过渡句不算衔接，仍按“口语词与套话”一节删除。
连接词表示的关系与实际不符时，比没有连接词更误导读者。
例如用“不仅……而且……”“一方面……另一方面……”连接两个既不递进、也不对举的普通事实。
“上述”“如前所述”“基于上述分析”“鉴于此”同理，只在前文确有所指、后文确实由此推出时使用，不用来粘合没有关系的句子。

例如下面两句之间是转折关系，原文没有交代。

> 该方法在小样本场景下表现稳定。训练时间是基线方法的 3 倍。

这层关系只起串联作用，用“但”把两句连起来即可。

> 该方法在小样本场景下表现稳定，但训练时间是基线方法的 3 倍。

下面三句中，最后一句与读者的预期相反，原文却没有说明原因。

> 截断样本的奖励统一记为 0。A 组的截断率最高。A 组的奖励方差最低。

这时因果关系本身就是读者需要的信息，值得单独写一句。

> 截断样本的奖励统一记为 0。A 组的截断率最高，奖励方差却最低。这是因为 A 组超过 80% 的样本被截断，大部分奖励都是 0，取值高度集中。

### 3.2 修饰语层数

名词短语要让读者读一遍就能理清其中几个概念的关系。
定语嵌套超过两层时，读者往往要回头重读。
这时先检查能否把内层概念拆出来，用一句话说清，再补上外层的修饰。
已经固定的术语算作一个单位，例如“单点系泊系统”“有效波高”，不拆开计算层数。

“本文提出了一种用户行为数据分析模型优化方案”就需要拆开，改成两句后，模型、数据与方案的关系才清楚。

> 本文研究的模型用于分析用户行为数据。针对这一模型，本文提出了一套优化方案。

### 3.3 抽象主语

以抽象概念作主语、搭配字面上只有人或生物才能发出的动作的句子，容易让读者看不出到底是谁做了什么、观测到了什么。
“这个框架吞噬了……”“这条规则抓住了……”“这个机制驱动了……”单独看都能读懂。
这类句子在同一段里密集出现时，读者的理解负担会不断累积。
遇到这类句子，先检查能否把主语还原成具体的人、事物或场景。
这类句子密集的段落优先改写。
主语是文本中的成分本身、指代明确时，例如“这类结构”“这些说法”，不属于这个问题。
主语搭配“提高”“降低”“导致”等常规动词时，例如“该方法提高了准确率”，不属于这个问题。
主语本身没有问题、只是动词与宾语不搭配的，按“搭配检查”一节处理。

写学术文本时，也不把动机、意愿与感受赋予模型、指标、程序或数据。
改写这类表述时，同样把动作还原为可观测的量与条件。

| 原表述                         | 改写                         |
| ------------------------------ | ---------------------------- |
| 模型学会了偷懒，专挑短答案作答 | 训练后模型生成的回答明显变短 |
| 优化器急于压低损失             | 损失在训练初期下降很快       |
| 该指标渴望更多样本             | 该指标需要更多样本才能稳定   |
| 数据拒绝支持这一假设           | 数据与这一假设不一致         |

### 3.4 搭配检查

逐句检查名词与动词的搭配，问自己其他研究者会不会这样说或这样写。
他们不会用的搭配，换成他们会用的说法。
每个字都认识、连在一起却别扭的表述，就是需要换的。

| 原表述                         | 改写                         |
| ------------------------------ | ---------------------------- |
| 实验结果夯实了这一假设         | 实验结果支持这一假设         |
| 该方法打通了标注与训练两个环节 | 该方法把标注结果直接用于训练 |
| 模型的鲁棒性实现了跃升         | 模型的鲁棒性明显提高         |
| 该指标承载了模型的泛化能力     | 该指标反映模型的泛化能力     |

## 4 人类作者的写法

“常见痕迹”一章说明哪些写法要避免，本章说明研究者在同样位置通常怎样写。
下列写法都要以素材中实际存在的事实、判断与经历为基础，素材中没有的，不为模仿而编造。

### 4.1 判断的确定程度

研究者会逐条区分哪些判断已经验证，哪些只是推测，哪些比较根本没有做过。
大语言模型则倾向于让全文保持同一种确定程度，要么处处肯定，要么处处含糊。
确定程度取决于“写作前的判断”中分清的素材来源，写作时把它落实到每一个判断上。

没有做过的比较或测试会影响结论时，直接写明没有做，并说明它影响哪一项结论。
这类说明写在哪里、写几次，按“失败、代价与局限”一节处理。
作者自己的推测可以写，但要标明是推测，并写出支持它的依据或能够检验它的方法。
实验结果推翻了作者原先的预期时，可以先写预期，再写结果，这比只写结果更能说明这项结果的意义。

> 位置向量与输入逐元素相乘时，模型在两个数据集上的困惑度比相加时分别低 0.4 和 0.6。本文没有在其他任务上比较这两种组合方式，这一差异是否普遍尚不清楚。

### 4.2 有依据的取舍与批评

比较前人工作或候选方案时，研究者会说明哪一个更好、哪里有问题、自己为什么不用。
理由落在具体的条件和后果上，不停留在“各有优劣”。
大语言模型常常把每种方法都描述得同样合理，读者看完仍不知道该选哪一个。

批评指向具体的设计、实验或表述，并说明它造成的后果，例如某个简称与领域内已有术语重名，容易引起误解。
不出于礼貌把有依据的批评改写成中性描述，也不为显得有立场而补充没有依据的批评。

下面这句话没有说明优势在哪里，也没有说明本文的选择。

> 两种方法各有优势，适用于不同场景。

改写后，取舍的条件和结果都写了出来。

> 方法 A 不需要标注数据，但每次推理要做两次前向计算。方法 B 需要标注数据，推理只做一次前向计算。本文已有标注数据，应用场景又对延迟要求严格，因此选用方法 B。

### 4.3 解释的层次

解释一项结果为什么成立时，研究者常常先给出直接原因，再追问这个原因为什么成立，直到落在读者已经接受的事实上。
另一种常用的写法是拿一个失败或低效的方案作对照，说明成功的方案避开了什么。
只给出第一层原因的解释，读者往往无法判断它在其他条件下是否仍然成立。

> 学习率预热降低了训练初期的损失震荡。去掉预热后，前 500 步的单步参数更新幅度是有预热时的 6 倍，打乱数据顺序后差距不变，因此震荡来自过大的参数更新，而不是数据顺序。更新幅度过大，是因为训练初期的梯度方向还不稳定，此时使用完整的学习率会让参数沿不准确的方向走得过远。预热在这一阶段把学习率调小，缩小了每一步的更新幅度。

### 4.4 单个例子的展开

支撑一个论点时，研究者通常只用一个例子，但把它展开到能独立支撑结论。
展开的意思是给出具体取值，写出中间步骤，并指出论点在哪一步得到体现。
大语言模型倾向于并列几个一句话的例子，每个例子都没有展开，读者只能自己补全推理。
只支持同一结论的多个例子、类比或案例，保留最贴切的一个，再按本节展开。
这里的例子指用来说明论点的例子，不包括多个数据集或多组实验的结果。

下面的例子给出了取值和中间步骤，读者可以直接看出两种计算量之比就是 w/n。

> 局部注意力把计算量从 O(n²) 降到 O(nw)。序列长度 n 为 8192、窗口 w 为 512 时，全局注意力要计算约 6711 万个打分，局部注意力约 419 万个，减少到原来的 1/16，正好等于 w/n。

### 4.5 文献之间的关系

综述前人工作时，研究者会写清楚一个想法的来龙去脉，例如谁最早提出，谁改进了哪一点，哪种做法因为什么原因流行起来，后续工作沿用了什么。
大语言模型常常写成“文献 A 提出了……，文献 B 提出了……”的平铺罗列，读者看不出这些工作之间是继承、改进还是竞争。

> 文献[3]提出了相对位置编码。文献[5]提出了一种新的位置编码。文献[7]提出了一种更简单的位置编码。

改写后，每篇文献都交代了它与前人工作的关系。

> 相对位置编码最早由文献[3]提出，它只在注意力中引入截断后的相对距离。文献[5]沿用了相对距离的思路，并把注意力打分完全展开，用两个可训练向量替换了查询一侧的位置项。文献[7]在此基础上删去输入与位置的交叉项，只保留一个按相对距离分桶的偏置。

### 4.6 失败、代价与局限

研究者会报告没有成功的尝试、方法付出的代价，以及事后看来不对的判断，并说明原因。
失败的尝试如果能解释最终方案为什么这样设计，就写进正文。
局限要写到具体条件，即在什么设置下结论可能不成立，以及为什么。
“样本量有限”“未来可在更大规模数据上验证”这类局限可以放进任何论文，不提供信息。
素材中有具体条件时，按具体条件改写，没有时删除。

> 本研究存在一定局限，未来可进一步扩展。

改写后，读者知道结论在什么范围内成立。

> 所有实验都在单卡上完成，批大小不超过 256。多卡训练时梯度同步是否改变结论，本文没有测试。

局限只写可能改变结论的那几项，每一项在全文只交代一次。
交代的位置是数据或方法首次说明处，或者局限部分。
只有某个结论受这项局限的影响与其他结论明显不同时，才在该结论处再提一次。

## 5 常见痕迹

下列写法在大语言模型生成的学术文本中出现频率很高。
示例只用来说明边界，不必逐字匹配。
其中修辞句式、常用连接词与标点单次出现可能是作者有意为之，连续出现或模式化使用时才改，各小节另有说明的除外。

### 5.1 意义夸大与空泛评价

这类表达常带有“填补了空白”“具有重要的理论意义和实践价值”“标志着”“里程碑”“开辟了新路径”“奠定了坚实基础”“深远影响”“彰显”“前景广阔”等词。
大语言模型习惯在事实之后追加一句评价，宣称它重要、深刻或具有范式意义。
判断时设想删去这句话，信息量没有减少就直接删除。
句尾追加的抽象评论同样处理，如果评论确有依据，就把依据写成独立的事实句。
“挑战与展望”式的模板段落也要删除，只保留其中可核实的事实。

引言和结论是例外，这两处确实需要说明研究意义。
这时不能直接删除，而要写清楚这项研究解决了谁的什么问题，依据是什么。

下面这句话的后半句只是评价，删除后信息量没有减少。

> 该数据集包含 12 万条样本、覆盖 8 个领域，规模庞大、质量上乘，为后续研究奠定了坚实基础。

修改后只剩事实。

> 该数据集包含 12 万条样本，覆盖 8 个领域。

### 5.2 模糊归因与未查明的因果

“研究表明”“学界普遍认为”“有观点认为”“大量研究证实”这类说法把观点挂在无名的权威身上。
学术文本中的观点都要有出处。
引用他人观点时，写明具体文献。
出处只能来自用户提供的素材，或本次实际检索并核实过的文献，不凭记忆补写作者、年份、题名或编号。
找不到出处的观点，改写成作者自己的判断并给出依据，或者删除，起草时也可以按“写作前的判断”一节留下占位符。
罗列一串文献编号来壮声势、却不说明各篇具体结论的写法，处理方法相同。

原因尚未确认时，直接写“原因尚未查明”，不补充听起来合理但未经验证的解释。
前文已写明原因未查明的，后文也不把其他现象归因于这一原因。
后续章节如果查明了机制并给出验证过程，相应结论可以保留。

| 原表述                     | 改写                                   |
| -------------------------- | -------------------------------------- |
| 原因不复杂，是因为……       | 原因已验证时直接陈述，未验证时删除该句 |
| 这可能也解释了前文那个现象 | 该现象与截断的关系尚未验证             |

### 5.3 术语与自造概念

概念已有通用说法时，使用通用说法，不用口语描述、比喻或临时命名替代。
一个说法如果需要读者推断它指什么，就改为直接说明所指的事实。

| 原表述               | 改写                        |
| -------------------- | --------------------------- |
| 超长度               | 截断                        |
| Ray 的端口会跟自己撞 | 多个任务的 Ray 抢占同一端口 |
| 刷奖励               | reward hacking              |
| 8 个不同血统         | 8 个不同基座的模型          |
| 已经吃掉一半空间     | 已覆盖一半区间              |
| 误差范围还盖着基准线 | 置信区间与基线重叠          |

大语言模型还会把普通现象压缩成听起来正式的概念，例如“监督悖论”“加速陷阱”“能力鸿沟”，用命名代替解释。
临时概括不能写成已有术语。
确实需要简称时，先给出操作性定义，并说明这是本文使用的称呼。

英文缩写在摘要和正文中第一次出现时都要注释，之后只用缩写。
这是学术期刊的通行要求，同行熟悉的缩写也不例外，期刊或用户另有规定时从其规定。
有正式中文译名的，先写中文译名，再在括号内写英文全称和缩写，例如“欧洲中期天气预报中心（European Centre for Medium-Range Weather Forecasts，ECMWF）”。
没有正式中文译名的，直接写缩写，括号内写英文全称，例如“MFWAM（Météo-France Wave Model）”。

比喻只用来帮助理解当前内容，不作为术语在全文反复替代原概念。
同一比喻多次出现时，保留最有效的一处，其余改回实际对象。
称呼同理，同一对象在全文使用同一个名称，不为避免重复而轮换说法。
表头、分类名与状态标签也使用同一套名称。

### 5.4 对比与戏剧化句式

“是 X，不是 Y”“不仅……更是……”一类结构靠对比制造强调。
写作时直接写出观测结果，需要比较时给出两侧的具体取值。
“更关键的是”“这才是问题的本质”“很多人没有意识到”等说法则先宣告某项发现重要，结论放到后面才给出。
这类过渡句如果只用于制造悬念，就直接删除。
确实要判断某项因素更关键时，说明比较对象和依据。

自问自答、连续否定、独立短句和重复句首也属于戏剧化节奏。
自问自答只在引出真实的研究问题时保留，问题之后要接检验或论证。
只为引出现成答案的设问，即使只出现一次也删除，改为陈述答案。
多个短句表达同一层意思时，合并为完整的句子。

| 原表述                                               | 改写                                 |
| ---------------------------------------------------- | ------------------------------------ |
| 梯度对齐：是噪声，不是信号                           | 梯度对齐的三项检查结果均在噪声范围内 |
| 越稳定的指标越挑不出东西，越挑得出东西的指标越不稳定 | 重合率与取值数量呈反向关系           |
| 结果呢？很严重。                                     | 错误率从 2% 上升到 11%               |
| 没有解释。没有证据。只有结论。                       | 这项结论没有附带解释或证据           |

### 5.5 口语词与套话

口语词在学术文本中往往表达不出确切含义，应改为量值或标准说法。

| 原表述                           | 改写                                 |
| -------------------------------- | ------------------------------------ |
| 赢得很干脆                       | 差值为 0.030                         |
| 基本上等于抓阄                   | 接近随机选取                         |
| 本来就分不出高下                 | 真实差距低于可分辨范围               |
| 有事后找补的嫌疑                 | 该切分方式可能是在观察结果之后确定的 |
| 既然预测这条路走不通，那就退一步 | 删除该句，直接进入实验设置           |

“此外”“然而”“综上所述”“深入探讨”“至关重要”“不可或缺”“赋能”这类词在大语言模型生成的文本中常常成串出现，这时要逐个检查能否删除或换成更朴素的说法。
其中“此外”最常被误用，它只表示补充，前后实际是因果或转折时，按“逻辑衔接”一节处理。

其余常见的套话按下列方式处理。

- 不承载信息的填充短语与教学腔直接删除，如“需要指出的是”“值得注意的是”“下面逐步分析”“不妨这样理解”
- 名词化的动词改回动词，“对……进行了优化”写作“优化了”，“实现了……的构建”写作“构建了”，“起到了促进作用”写作“促进了”
- “被广泛应用于”“被认为是”这类隐去出处的被动句，改为主动句并写出施事，写不出施事的按“模糊归因与未查明的因果”一节处理，“样品被加热至 80 °C”这类描述实验操作的被动句不在此列
- “通过……，使得……”会让句子失去主语，“通过引入注意力机制，使得模型性能得到了提升”写作“引入注意力机制后，模型性能提高了”
- 用“作为……”“扮演着……的角色”回避简单的“是”和“有”时，改回“是”和“有”
- 层层叠加的限定词只保留一个与证据强度相符的，如“可能在一定程度上或许会”只留“可能”
- 不用“一句话概括”“简单来说”后接对仗短句的方式收束，确需总结时用陈述句写进段落
- “从 X 到 Y”的两端不在同一尺度上时，改为直接列举

### 5.6 段落与篇章

大语言模型生成的段落常以“标签：内容”开头，例如“核心发现：……”“方法局限：……”“研究结论：……”。
这样写会把本该写进首句的信息压成一个名词。
修改时把标签的意思写进段落的第一句。
如果它确实是一个独立的部分，就升级为小标题。
列表项机械地以“**名词**：”开头属于同一问题，标签没有分类作用时，改成普通句子。

编号列表用于有先后顺序的步骤，无序列表只用于确实并列、彼此独立的条目，例如实验参数和样本纳入标准。
论证、因果、递进与比较都写成段落。
把一段论证拆成几条孤立的要点后，条目之间的关系就丢了，读者看不出思路怎样从一点推进到下一点。
反过来，确属并列的信息也不必改写成以“首先、其次、最后”开头、结构相同的几段。

段落结构和段内句式同样不能千篇一律。
大语言模型常常让每段都先给结论句，再列三条理由，最后用一句话收束。
段内的句子也多是长度相近的主谓宾陈述句。
实际写作中，段落应按内容组织，有的从现象写到解释，有的从问题写到回答，有的先摆数据再下判断。
句子长短随信息量变化，但不为制造变化而插入修辞。
并列项的数量同样由内容决定，不为凑足三项而补入，也不为避开三段式而删成两项。

在章节层面，预告和小结只在能帮读者理清长篇结构时使用。
例如学位论文在章首交代本章与上一章的关系，在章末给出由前文推导出的判断或后续工作。
逐项预告接下来要写什么，或者在结尾复述刚写过的结论，都不增加信息，应当删除。
摘要和结论按研究问题、方法要点与主要发现组织，不按“本文首先……接着……最后……”的章节顺序复述。

重复还有一种不那么明显的形式，就是把一个观点靠更换措辞、例子或比喻扩写成多个段落或章节。
检查每一段是否增加了新事实、新论证或新的限定条件，没有新增内容的段落合并或删除。
已经交代过的设定或结论，后文用到时直接使用，不在每段重新强调。

类比和案例的堆叠也是同一类问题，连续列举类比或案例并不能代替论证。
每个类比都要说明它与当前问题对应的条件和不对应的边界。
只支持同一结论的多个类比或案例，按“单个例子的展开”一节处理。

用强化学习做过后训练的大语言模型还常有一种防御式写法，即为了让结论不被挑出毛病，在几乎每段都重复同一项局限。
例如研究报告每段都写一句“仅使用再分析数据，未使用现实观测”。
这样写不会让研究显得更严谨，反而会让读者怀疑整项研究是否可信，研究目标和主要结论也被淹没。
修改时按“失败、代价与局限”一节只保留一处，其余删除。

### 5.7 标题、表格与格式

章节标题、表头与分类名使用中性的名词短语，如“实验设置”“结果”“讨论”“局限”。

| 原表述               | 改写             |
| -------------------- | ---------------- |
| 坑、代价和教训       | 问题、影响       |
| 怎么做的             | 实验设置         |
| 重挑一次还剩多少重合 | 重采样后的重合率 |
| 有几种不同取值       | 取值数量         |
| 做通了               | 已完成           |
| 没有买到想要的       | 结论待定         |

箭头、表情符号与连续标点如果只用于制造视觉强调，改为文字或删除。
破折号、冒号、问号与感叹号按语义使用。

括号会打断阅读，非必要不用。
必要的情形包括全称与缩写的对应注释、“（1）”这类序号，以及公式、单位与引文编号中的惯例用法。
按期刊要求的统计报告格式放在括号内的检验结果，也属于必要情形。
坐标、时段、拟合优度这类能写进句子的补充信息，直接写进句子。

并列的名词之间用顿号或“与”“和”，不用破折号、连字符或斜杠串联，例如“政府—学校—企业”应改为“政府、学校与企业”。
连接号或斜杠表示的不是简单并列时，按学科惯例保留。
例如“海洋—大气耦合模式”“应力—应变曲线”表示相互作用或对应关系，“水/油界面”“气/液两相流”表示界面或相态。
用户提供的素材中已有的连写可以沿用。

### 5.8 对话残留

学术写作的正文中不能出现对话或聊天式的句子。
这类句子主要来自大语言模型的对话式回复，包括协作语气和模型的自述。
常见的例子有“这是一个很好的问题”“希望这对你有帮助”“如果需要我可以进一步展开”“截至我的知识截止日期”。
这类内容一律直接删除，无需替换。

用户在对话中提出的写作要求也会残留在正文中。
要求是对写作的约束，不是写给读者的内容，满足要求即可，不在文中复述。
用户比模型更了解实际情况，被用户否定的方案也不再作为备选交给读者。
例如用户要求删去政策建议后，正文就没有政策建议，不再出现下列写法：

- 标题加上“（不含政策建议）”之类说明要求的标注
- 正文写“根据要求，本文不讨论政策建议”
- 结论末尾补充“如有需要，也可从政策层面进一步展开”

要求如果同时决定了研究范围，例如限定了研究区域或数据来源，就作为研究设计写一次，素材中有理由时一并写明，不提及用户。
需要告诉用户的改动，写进交付说明，不写进正文。
