# WOSCC 论文检索与研究进展总结

使用纯 HTTP 接口检索 Web of Science Core Collection，获取索引元数据和摘要，筛选相关论文并给出有来源的结论。
把 TSV 与 JSONL 视为内部中间产物；除非用户明确要求导出，否则不向用户交付或强调文件路径。

## 核心约束

- 始终把检索集合称为 WOSCC，不把未限定的 WOSCC 结果称为 SCI、SCIE 或 ESCI 结果
- 用户明确指定 SCIE、ESCI、SSCI、A&HCI 等 citation index 时，使用 TSV 的 `WE` 列严格后过滤；当前没有已验证的服务端 edition 参数，不要猜测 `ED=`、`WE=` 或 `editions` 查询参数
- 不下载或访问论文全文，不调用任何全文获取工具；全文需求只提供 DOI，并说明需由用户自行通过出版社或图书馆获取
- 只依据题名、关键词和摘要做相关性筛选及研究进展归纳，不得把摘要级判断表述为已核验全文的结论
- 不泄漏机构名称、邮箱、出口 IP、SID 或其他会话信息；谈及授权时只说“机构网络、校园网或机构 VPN”
- WoS 网络请求必须顺序执行，只有本地记录筛选才可并行；默认单次最多取回 1000 条，超过时必须得到用户对批量采集的明确确认

## 任务路由与投入档位

先识别任务，再选择最短的可靠路径：

| 任务                                   | 路径                                                           |
| -------------------------------------- | -------------------------------------------------------------- |
| DOI、UT、精确题名定位                  | 精确查询；通常走快速档，不做批量二次筛选                       |
| 单篇或少量论文的元数据、WOSCC 被引次数 | 精确查询后直接呈现；需要 Z9、关键词、卷期页或 CR 时改走 TSV    |
| 明确主题、作者、期刊、年份的代表性论文 | 标准档：计数、必要时收窄、TSV 获取、三态筛选                   |
| 宽主题、概念演进、最新进展或系统性收集 | 深入档：先确认范围和成本，再执行多个查询变体、去重、筛选和综合 |
| 用户明确要求导出                       | 在对应检索路径完成后交付已过滤的 TSV 或 DOI 清单               |
| 全文与 PDF                             | 不执行全文获取；只返回 DOI 和获取建议                          |

三种投入档位：

- 快速: 一个精确或窄检索式，通常不超过 20 条；不限定 citation index 且 JSON 字段足够时优先 JSON，由主代理直接筛选
- 标准（默认）: 一个主检索式，必要时迭代 1 至 2 次，通常不超过 200 条；优先 TSV 路径，使用确定性过滤和三态语义筛选
- 深入: 仅在用户确认后使用；约定年份、citation index、文献类型、查询变体、数量和时间预算，默认不超过 1000 条候选，更大规模另行确认批量范围

根据用户目标而不是固定命中阈值决定档位。
精确查询可跳过计数。
宽主题若用户本来需要研究全景，不要强迫缩成单点问题，改用年份、文献类型和数量预算限定成本。

## 执行流程

1. 规范化需求: 确认研究概念、年份、文献类型、citation index、用途和期望投入；用户已给足信息时不重复提问
2. 确认外部动作: 直接的 WoS 检索请求视为用户已授权；模式 B、深入档和超过 1000 条的批量任务必须先提醒并取得确认
3. 制定检索计划: 生成查询式、排序、取回上限和 edition 后过滤计划；把 SCI 规范化为 SCIE，把 SCIE 规范化为导出代码 `SCI-EXPANDED`
4. 临执行前探查权限: 每个会话探查一次；无授权时停止 WoS 流程，不反复探测
5. 选择数据路径: 仅快速档、未限定 citation index 且常用字段足够时使用 JSON，其他情况优先 TSV；edition 限定默认必须完整获取当前查询的全部 `recordsFound` 后按 `WE` 过滤，脚本会拒绝截断；只有用户明确接受“WOSCC 排序前 N 条中的 index 子样本”时才允许截断，并必须标明不完整
6. 获取并规范化记录: 使用 `scripts/wos_search_tsv.py`；TSV 路径同时产生规范化 JSONL，深入档有多个查询时再用 `scripts/merge_filter_jsonl.py` 合并、去重并执行硬过滤；后续语义筛选只消费 JSONL，不让筛选代理自行解析原始 TSV
7. 筛选与综合: 先执行年份、类型、edition、显式关键词等确定性过滤，再做入选、排除、不确定的三态语义判断；缺摘要或必须阅读全文才能判断时使用“不确定”
8. 呈现和收尾: 回答用户问题、列出代表性论文并给出紧凑方法摘要；默认不交付中间文件，让会话临时目录负责清理

## 模式 B：讨论中的证据增强

仅当最新 WoS 索引研究证据可能实质改变或支撑当前科研讨论时，在自然停顿处提醒一次，并给出快速、标准、深入三个选择及大致成本。
用户拒绝后，本次讨论不再提醒。
若用户要求同行评议材料，应明确限制并报告 Article、Review 等文献类型，不把“已被 WOSCC 收录”自动等同于“已核验同行评议”。

确认后只允许一个 worker 顺序访问 WoS，由主代理组织本地筛选和最终综合。
支持后台 worker 时主对话可继续；不支持时如实说明需要等待，不承诺异步或嵌套代理能力。

## 最终交付要求

- 关键论文默认给出标题、首位作者、来源、年份、WOSCC 被引次数和 DOI；缺 DOI 时给 UT
- 把“近期代表作”和“高被引基础作”分开；被引次数只描述传播情况，不代替质量或相关性判断
- 每个研究现状要点至少关联一篇支持论文；无法由摘要直接支持的推断标为不确定或需全文确认
- 始终附简短方法摘要，包含检索日期、Collection、citation index、检索式与年份、命中与取回数量、排序与截断、摘要级局限；未执行语义筛选的快速查询或纯导出，把筛选、入选、不确定数量标为“不适用”
- 只有用户明确要求导出时才提供 TSV、JSONL 或 DOI 清单
