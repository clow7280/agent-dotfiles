# 文献类型与载体代码（附录 A）

按资源的实际形态选“文献类型”，按使用介质选“载体”。电子资源必须同时写两者：`[类型/载体]`。

## 选择顺序

1. 先判断资源是不是另一专门类型，再判断它是否在线。
2. 在线期刊论文用 `[J/OL]`，不要因浏览器访问而改成 `[EB/OL]`。
3. 在线图书用 `[M/OL]`；书中章节仍以析出文献模板著录，类型通常继承为 `[M/OL]`。
4. 在线报纸文章用 `[N/OL]`。
5. 会议论文/会议录按资源形态用 `[C]` 或 `[C/OL]`。
6. 学位论文、报告、标准、专利、档案、地图、数据集、预印本各用专门代码。
7. 只有不能归入专门类型的一般网站或网页才用 `[EB/OL]`。
8. 网页实际提供的是软件程序时，可按资源本体用 `[CP/OL]`，而非一律 `[EB/OL]`。
9. `Z` 只作无法归入任何已列类型时的兜底；不得为了省事替代可识别类型。

### `G`、`CP`、`DB`、`Z` 的模板路由

附录 A.1 只给出这四类的类型代码，第 8 章没有为它们另设一套统一著录项目表或通用模板。因此：

1. 先辨明资源实际的出版和呈现形态，再选择第 8 章有依据的相近结构，同时保留对象的实际类型代码。
2. 第 8.11.3 条示例中的 Zotero 下载页证明软件可按网页字段顺序著录并保留 `[CP/OL]`；这不等于所有 `CP`、`DB`、`G` 或 `Z` 都是网页。
3. 不得仅凭代码补造出版地、发布平台、引用日期或其他字段，也不得声称标准为这四类规定了统一模板。
4. 形态不能确定，或没有可类比模板时，保留可确认字段并列为待核。上述“按形态路由”是本 skill 为处理标准模板空白而采用的保守工作规则，不冒充标准原句。

## 组合与标点

- 纸质或非电子资源通常只写 `[M]`、`[J]` 等类型代码。
- 电子资源写 `[J/OL]`，斜线只连接类型与载体，不写成 `[J][OL]` 或 `[OL/J]`。
- 代码使用大写拉丁字母；`OL` 中是字母 `O` 和 `L`，不是数字 `0`。
- 类型/载体标识放在该类型模板指定的题名段末端：通常紧跟题名或其他题名信息；报告编号、专利申请号、档号、地图比例尺等在模板中位于题名与类型标识之间时，应先著录这些字段，再写类型/载体标识。其后通常以句点进入下一字段。
- 不把正文引文序号 `[12]`、引用日期 `[2025-07-16]` 与类型代码混淆。

## 容易混淆的边界

| 输入对象 | 优先代码 | 理由 |
|---|---:|---|
| 期刊官网上的正式论文 | `J/OL` | 资源本体是连续出版物析出文献 |
| 报社网站上的报纸版文章 | `N/OL` | 资源本体是报纸析出文献 |
| 机构官网发布、具有报告属性的白皮书 | `R/OL` | 资源本体是报告 |
| 机构官网普通介绍页 | `EB/OL` | 不属于更专门类型的网页 |
| 数据仓储中的数据记录 | `DS/OL` | 数据集专门类型 |
| arXiv/ChinaXiv 等未正式同行评审版本 | `PP/OL` | 预印本专门类型 |
| 正式期刊版与其预印本 | 分别 `J/OL`、`PP/OL` | 是两个版本/资源，不应无提示合并 |
| 在线交互地图 | `CM/OL` | 地图专门类型 |
| 软件下载安装页所指的软件 | `CP/OL` | 著录对象是程序时用 CP；若著录介绍网页则可用 EB |
| 在线书目/事实数据库 | `DB/OL` | 资源本体是数据库 |

若对象边界不明，先写明“著录对象”是网页本身、网页中的文件，还是文件所表达的作品，再选代码。
